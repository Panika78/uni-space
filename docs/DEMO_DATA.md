# Демонстрационные данные MVP 1

`backend/scripts/seed_demo_data.py` — отдельная явная команда для демонстрационной
БД. Скрипт использует существующие сущности и роли; миграции и запуск API его не
вызывают. Первый запуск разрешён только после миграций на выделенной чистой БД
(допускаются созданные миграцией `service_types`). Runtime-роль `uni_space_api`
отклоняется. Пользовательские заявки, их статусы и отметки прочтения уведомлений
не входят в управляемые seed данные.

## Состав и даты

Вымышленный университет использует обычную структуру справочника:

| Факультет | Программа | Группа | Курс | Студент |
|---|---|---|---:|---|
| Факультет естественных наук | Прикладное зельеварение (`ПЗ`) | ПЗ-101 | 1 | Иван Сергеевич Гончаров (`demo-pz101`) |
| Факультет естественных наук | Прикладная мантика и прогностика (`ПМ`) | ПМ-201 | 2 | Амели Викторовна Волкова (`demo-pm201`) |

Большинство дисциплин — общеобразовательные и естественно-научные; профильные
предметы дополняют планы. У Ивана показаны текущие работы с нулём и без оценки;
первую сессию он ещё не сдавал, предыдущих семестров и выдуманной задолженности
нет. Амели показана с положительными текущими результатами. У студентов разные
группы, дисциплины, оценки и персональные уведомления.

Учебный период: 1 сентября 2026 — 31 января 2027. Недельные шаблоны раскрываются
в отдельные записи `lessons`; серий и редактора повторяющихся занятий в модели и
API нет. Время задано для `Europe/Moscow`. План исключает выходные и 4 ноября;
конкретные записи ограничены датами семестра. Три новости опубликованы 8–10
ноября 2026 года.

Специальные изменения относятся к четвергу, 19 ноября 2026 года: лабораторная
ПЗ-101 в УЛК отменена; занятие по введению в зельеварение перенесено с 19 на 20,
затем на окончательную дату — 23 ноября 2026 года — в ГУК; практикум ПМ-201
перенесён с 19 на 21 ноября в Северную башню. Цепочки связаны через
`previous_lesson_id`, новость сообщает конечную дату. Генератор проверяет
пересечения активных занятий по времени, аудитории, преподавателю и группе.

Даты фиксированы, а не вычисляются при запуске. После 31 января 2027 года период
перестанет считаться текущим в `GET /academics`: для следующей демонстрации нужно
подготовить и проверить новый набор дат. Не запускайте seed для сдвига периода.

## Локальный запуск

Создайте `.env` по README, поднимите PostgreSQL и примените миграции. Команды
выполняются из корня репозитория в Bash. Пароли вводятся скрыто и передаются
только через окружение процесса; seed сохраняет только Argon2id-хеши.

```bash
set -a
source .env
set +a
read -r -s -p 'Пароль ПЗ-101: ' DEMO_STUDENT_A_PASSWORD; printf '\n'
read -r -s -p 'Пароль ПМ-201: ' DEMO_STUDENT_B_PASSWORD; printf '\n'
export DEMO_STUDENT_A_PASSWORD DEMO_STUDENT_B_PASSWORD
export DEMO_SEED_ALLOWED_DATABASE="$POSTGRES_DB"
export DEMO_SEED_ALLOWED_HOST=db
export DEMO_SEED_CONFIRM="SEED_UNI_SPACE_DEMO_DATA:$POSTGRES_DB@db"
docker compose run --rm \
  -e DEMO_STUDENT_A_PASSWORD -e DEMO_STUDENT_B_PASSWORD \
  -e DEMO_SEED_ALLOWED_DATABASE -e DEMO_SEED_ALLOWED_HOST -e DEMO_SEED_CONFIRM \
  api python scripts/seed_demo_data.py
unset DEMO_STUDENT_A_PASSWORD DEMO_STUDENT_B_PASSWORD DEMO_SEED_CONFIRM
```

Подтверждение содержит точные значения базы и host из `DATABASE_URL`.
В `development`/`test` допускается только явно выбранная отдельная БД. Первый
запуск откажет при наличии пользовательских записей. Пароли должны быть разными,
не короче 12 символов и передаваться без внешних пробелов.

Повторяйте ту же команду только для той же выделенной БД и с теми же паролями.
Идентификаторы аккаунтов и связей сохраняются. Существующие пароли проверяются;
при несовпадении транзакция отменяется, ротации нет. Отключённый аккаунт не
активируется повторно. Переименование прежнего ПЗ-101 выполняется только если
seed подтверждает профиль, группу и программу; иначе запуск откажет. Не удаляйте
строки вручную для «починки» seed. Неоднозначные или изменённые seed записи
требуют ручного расследования, seed завершится безопасным отказом.

## Проверка перед показом

Перед выдачей доступов примените миграции, seed и проверки:

```bash
(cd backend && uv run --locked --python 3.12.16 alembic upgrade head)
(cd backend && APP_ENV=test DATABASE_URL="$DATABASE_URL" \
  uv run --locked --python 3.12.16 pytest tests/test_demo_seed.py -m integration -q)
```

Оператор проверяет оба входа по логинам из таблицы, профиль, текущие оценки,
расписание на день и неделю, новости, персональные уведомления и доступность
услуги. Создание заявки проверяется реальной отправкой формы и появлением записи
в базе; для демонстрации используйте пользовательский сценарий, не подменяя его
тестовой фикстурой. Пароли для жюри передаются только по защищённому каналу,
указанному организаторами конкурса. Не размещайте пароли, токены или секреты в
репозитории, README, CI, Docker-образах, командных аргументах или логах.

Если вход или показ прервался, выполните обычный logout/login и повторите
пользовательский сценарий. Не отправляйте форму повторно автоматически после
сетевой ошибки: сначала проверьте состояние в доступном интерфейсе. Отображение
списка созданных заявлений и восстановление результата после потери ответа
реализуются отдельно в TASK-014.

## Production

Для этого используйте только отдельную демонстрационную БД после резервной копии.
Пароли загрузите из защищённого хранилища или скрытого интерактивного ввода; не
кладите их в `PROD_ENV_FILE`, git, CI или build args. Production seed запускается
только явно в one-off контейнере `migrate` с ролью `uni_space_migrator`, точным
подтверждением host/database и флагом `DEMO_SEED_ALLOW_PRODUCTION` из раздела
production-команд README. Роль `uni_space_api` не получает дополнительных прав.
Повторный seed не является восстановлением backup и не заменяет проверку данных.
