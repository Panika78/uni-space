# Демонстрационные данные MVP 2

`backend/scripts/seed_demo_data.py` — отдельная явная команда для демонстрационной
БД. Скрипт использует существующие сущности и роли; миграции и запуск API его не
вызывают. Первый запуск разрешён только после миграций на выделенной чистой БД
(допускаются созданные миграцией `service_types`). Runtime-роль `uni_space_api`
отклоняется. Пользовательские заявки, их статусы и отметки прочтения уведомлений
не входят в управляемые seed данные.

## Состав и учебный период

Вымышленный университет использует обычную структуру справочника:

| Факультет | Программа | Группа | Курс | Студент |
|---|---|---|---:|---|
| Факультет естественных наук | Прикладное зельеварение (`ПЗ`) | ПЗ-101 | 1 | Иван Сергеевич Гончаров (`demo-pz101`) |
| Факультет естественных наук | Прикладная мантика и прогностика (`ПМ`) | ПМ-201 | 2 | Амели Викторовна Волкова (`demo-pm201`) |

Большинство дисциплин — общеобразовательные и естественно-научные; профильные
предметы дополняют планы. У Ивана показаны текущие работы с нулём и без оценки;
первую сессию он ещё не сдавал, предыдущих семестров и выдуманной задолженности
нет. Амели показана с положительными текущими результатами. У студентов разные
группы, дисциплины, оценки и персональные уведомления.

Учебный период: 1 сентября 2026 — 31 января 2027. Недельные шаблоны раскрываются
в отдельные записи `lessons`; серий и редактора повторяющихся занятий в модели и
API нет. Время задано для `Europe/Moscow`. План исключает выходные и 4 ноября;
конкретные записи ограничены датами семестра. Три новости опубликованы 8–10
ноября 2026 года.

В каждой группе по девять дисциплин. В ПЗ-101 это матанализ, история России,
иностранный язык, информатика, общая и неорганическая химия, введение в
зельеварение, травология, основы алхимического анализа и защита от тёмных
искусств. В ПМ-201 это теория вероятностей и математическая статистика,
иностранный язык, философия, физкультура и спорт, теоретические основы мантики,
практикум по гадательным системам, методы вероятностного прогнозирования, рунная
аналитика и защита от тёмных искусств. Недельный план ПЗ-101 содержит 19 занятий.
В расписании Амели 18 занятий: 16 общих для группы и два занятия практикума во
второй подгруппе. Первая подгруппа имеет три отдельных лабораторных занятия в
неделю. Подгруппы участвуют только в занятиях практикума; остальные предметы
доступны всей группе.

Десять преподавателей расписания имеют журнал-доступ через `teaching_assignments`:
Нина Белова, Виктор Громов, Людмила Соколова, Александр Морозов, Татьяна Егорова,
Елена Рябинина, Валентина Котова, Вадим Чернов, Маргарита Воронцова и Северин
Ворон. Только Северин имеет демонстрационный аккаунт. При создании остальных
преподавателей через штатную админку их расписание и журнал определяются уже
существующими назначениями. Семинарные работы привязаны к конкретным занятиям и
датам; отсутствие `AssessmentResult` означает, что оценка не выставлена, а запись
с `score = 0` является выставленным нулём.

Специальные изменения относятся к четвергу, 19 ноября 2026 года: лабораторная
ПЗ-101 в УЛК отменена; занятие по введению в зельеварение перенесено с 19 на 20,
затем на 23 ноября в ГУК; практикум ПМ-201 перенесён на 21 ноября в Северную
башню. Цепочки связаны через `previous_lesson_id`. Общая новость сообщает о
проверке и необходимости сверяться с расписанием, но не раскрывает конкретные
занятия и даты переносов. Эти подробности доступны студентам в персональном
расписании. Генератор проверяет пересечения активных занятий по времени,
аудитории, преподавателю и группе.

Даты фиксированы, а не вычисляются при запуске. После 31 января 2027 года период
перестанет считаться текущим в `GET /academics`: для следующей демонстрации нужно
подготовить и проверить новый набор дат. Не запускайте seed для сдвига периода.

## Опорная дата и окно конкурсной демонстрации

Опорная календарная дата сценариев — **19 ноября 2026 года по `Europe/Moscow`**.
Она выбрана как дата объявленного изменения расписания; итоговый перенос
проверяется в расписании на соответствующую дату. Конкурсное окно демонстрации —
**8–28 ноября 2026 года**.
Весь интервал находится внутри учебного семестра **1 сентября 2026 — 31 января
2027 года**, поэтому `GET /academics` на протяжении показа находит текущий семестр,
а расписание включает дни сценария и конечные позиции переносов. Результаты —
текущие результаты работ этого семестра; они не изображают завершённые сессии
или историю предыдущих периодов. API определяет текущий период по фактической
московской дате запуска, а не по этой опорной дате.

Перед показом в пределах окна проверьте `GET /academics`, `GET /schedule` и
новость об изменениях расписания; расписание должно показывать события 19, 20,
21 и 23 ноября, а общая новость не должна перечислять их. После 31 января 2027 года
текущий набор уже не подходит: подготовьте новый план на будущий период, пересогласуйте публикации,
оценки и даты, проверьте его на временной PostgreSQL-БД, затем отдельно примените
проверенный seed к демонстрационной БД после резервной копии. Не сдвигайте даты
автоматической заменой или повторным запуском seed.

## Локальный запуск

Создайте `.env` по README, поднимите PostgreSQL и примените миграции. Команды
выполняются из корня репозитория в Bash. Пять паролей вводятся скрыто и
передаются только через окружение процесса; seed сохраняет только Argon2id-хеши.

```bash
set -a
source .env
set +a
read -r -s -p 'Пароль ПЗ-101: ' DEMO_STUDENT_A_PASSWORD; printf '\n'
read -r -s -p 'Пароль ПМ-201: ' DEMO_STUDENT_B_PASSWORD; printf '\n'
read -r -s -p 'Пароль преподавателя: ' DEMO_TEACHER_PASSWORD; printf '\n'
read -r -s -p 'Пароль деканата: ' DEMO_DEAN_STAFF_PASSWORD; printf '\n'
read -r -s -p 'Пароль бухгалтерии: ' DEMO_ACCOUNTING_STAFF_PASSWORD; printf '\n'
export DEMO_STUDENT_A_PASSWORD DEMO_STUDENT_B_PASSWORD DEMO_TEACHER_PASSWORD
export DEMO_DEAN_STAFF_PASSWORD DEMO_ACCOUNTING_STAFF_PASSWORD
export DEMO_SEED_ALLOWED_DATABASE="$POSTGRES_DB"
export DEMO_SEED_ALLOWED_HOST=db
export DEMO_SEED_ALLOWED_PORT=5432
export DEMO_SEED_ALLOWED_ROLE=uni_space
export DEMO_SEED_CONFIRM="SEED_UNI_SPACE_DEMO_DATA:$POSTGRES_DB@db:5432/uni_space"
docker compose run --rm \
  -e DEMO_STUDENT_A_PASSWORD -e DEMO_STUDENT_B_PASSWORD -e DEMO_TEACHER_PASSWORD \
  -e DEMO_DEAN_STAFF_PASSWORD -e DEMO_ACCOUNTING_STAFF_PASSWORD \
  -e DEMO_SEED_ALLOWED_DATABASE -e DEMO_SEED_ALLOWED_HOST \
  -e DEMO_SEED_ALLOWED_PORT -e DEMO_SEED_ALLOWED_ROLE -e DEMO_SEED_CONFIRM \
  api python scripts/seed_demo_data.py
unset DEMO_STUDENT_A_PASSWORD DEMO_STUDENT_B_PASSWORD DEMO_TEACHER_PASSWORD \
  DEMO_DEAN_STAFF_PASSWORD DEMO_ACCOUNTING_STAFF_PASSWORD DEMO_SEED_CONFIRM \
  DEMO_SEED_ALLOWED_DATABASE DEMO_SEED_ALLOWED_HOST DEMO_SEED_ALLOWED_PORT \
  DEMO_SEED_ALLOWED_ROLE
```

В `development`/`test` подтверждение должно совпадать со всей явно выбранной
целью (host, port, database, role). Используйте только отдельную БД; первый
запуск откажет при наличии пользовательских записей. Пароли должны быть разными,
не короче 12 символов и передаваться без внешних пробелов. Seed создаёт ровно
пять аккаунтов: два студента, преподавателя Северина Ворона и двух сотрудников.
Администратор создаётся отдельно интерактивным `app.admin.bootstrap`.

Повторяйте ту же команду только для той же выделенной БД и с теми же паролями.
Идентификаторы аккаунтов и связей сохраняются. Существующие пароли проверяются;
при несовпадении транзакция отменяется, ротации нет. Отключённый аккаунт не
активируется повторно. Права сотрудников создаются вместе с новым профилем и не
восстанавливаются повторным запуском после отзыва. Преподавательские назначения
строятся из фактических занятий; существующие назначения seed не переписывает.
Переименование прежнего ПЗ-101 выполняется только если
seed подтверждает профиль, группу и программу; иначе запуск откажет. Не удаляйте
строки вручную для «починки» seed. Неоднозначные или изменённые seed записи
требуют ручного расследования, seed завершится безопасным отказом.

## Проверка перед показом

Перед выдачей доступов примените миграции, seed и проверки:

```bash
(cd backend && uv run --locked --python 3.12.16 alembic upgrade head)
(cd backend && APP_ENV=test DATABASE_URL="$DATABASE_URL" \
  uv run --locked --python 3.12.16 pytest tests/test_demo_seed.py -m integration -q)
```

Оператор проверяет входы всех пяти аккаунтов, профиль, текущие оценки,
расписание на день и неделю, новости, персональные уведомления и доступность
услуги. Матрица демонстрационных ролей:

| Роль / аккаунт | Область доступа | Сценарий и ожидаемый экран |
|---|---|---|
| Иван и Амели (`demo-pz101`, `demo-pm201`) | Собственный профиль, учебная группа и уведомления | `/schedule`, `/academics`, `/news`, `/notifications`, `/services` |
| Преподаватель (`demo-severin-voron`) | Только группы и дисциплины через `teaching_assignments` | `/teacher/schedule`, `/teacher/journals`, объявления по защите от тёмных искусств |
| Деканат (`demo-dean`) | Явные академические права без глобальной роли; заявления и новости в деканате | `/staff/students`, `/staff/academics`, `/staff/schedule`, `/staff/applications`, `/staff/news` |
| Бухгалтерия (`demo-accounting`) | Только `applications.review` в области бухгалтерии | `/staff/applications`; учебные маршруты должны отвечать отказом |
| Администратор | Только аккаунты и полномочия через admin API | `/admin/users`; создание преподавателя из справочника |

У деканата академические права `students.read`, `students.status.edit`,
`grades.edit`, `attendance.edit` и `schedule.edit` действуют в разрешённых API
границах; `applications.review` и `news.publish` ограничены подразделением
деканата. У бухгалтерии есть только `applications.review`, ограниченное её
подразделением. Создание аккаунта администратора не выдаёт сотруднику или
преподавателю дополнительных полномочий. Seed не восстанавливает отозванные
права; права сотрудников выдаются только при создании их профиля, а назначения
преподавателя, чей аккаунт уже существует, не пересоздаются после отзыва.

Иван относится к ПЗ-101 без подгруппы, Амели — ко второй подгруппе ПМ-201.
У ПМ-201 заведены две подгруппы. У каждого запланированного семинара есть
связанная утверждённая работа на 2 балла. Демонстрационные результаты заранее
подготовлены внутри фиксированного семестра; отсутствие `AssessmentResult`
означает отсутствие оценки, а `score = 0` — выставленный ноль. Если преподаватель
снимает оценку через API (`score: null`), повторный seed оставляет её снятой,
опираясь на сохранённое событие удаления в журнале. Посещаемость хранит пропуски
независимо от оценок. Seed не создаёт заявления.
Создание заявки проверяется реальной отправкой формы и появлением записи
в базе; для демонстрации используйте пользовательский сценарий, не подменяя его
тестовой фикстурой. Пароли для жюри передаются только по защищённому каналу,
указанному организаторами конкурса. Не размещайте пароли, токены или секреты в
репозитории, README, CI, Docker-образах, командных аргументах или логах.

Если вход или показ прервался, выполните обычный logout/login и повторите
пользовательский сценарий. Не отправляйте форму повторно автоматически после
сетевой ошибки: сначала проверьте состояние в доступном интерфейсе. Отображение
списка созданных заявлений и восстановление результата после потери ответа
обрабатываются существующими API MVP2.

## Production

Используйте только выделенную демонстрационную БД после проверенной резервной
копии. Сначала задайте `PROD_ENV_FILE` на приватный production env-файл по
`docs/PRODUCTION.md`, поднимите/проверьте `db` и примените миграции обычной
production-командой. Не запускайте seed на рабочей БД. Пароли загрузите из
защищённого хранилища или скрытого интерактивного ввода; не кладите их в
`PROD_ENV_FILE`, git, CI или build args.

Текущая production-конфигурация демонстрации закреплена в seed как
`db:5432/uni_space`, роль `uni_space_migrator`. Это ожидаемая идентичность из
версии приложения, она не вычисляется из `POSTGRES_DB` или `DATABASE_URL`. Если
в проекте Compose настроено другое значение, seed откажет: не меняйте ожидаемую
цель под случайную конфигурацию. Сверьте вывод проверки с тем, что это отдельное
демонстрационное окружение, а не рабочая БД. Перед запуском обязателен backup.

Запускайте команду в интерактивном терминале из корня проекта. Seed покажет
фактические host, port, database, role и адрес сервера (без паролей/секретов),
после чего запросит ввод фиксированной строки подтверждения ожидаемой demo-цели.
Не подставляйте в неё значения из текущего подключения. Production-флаг
разрешения нужен только для этой явной one-off операции:

```bash
set -a
source "$PROD_ENV_FILE"
set +a
read -r -s -p 'Пароль ПЗ-101: ' DEMO_STUDENT_A_PASSWORD; printf '\n'
read -r -s -p 'Пароль ПМ-201: ' DEMO_STUDENT_B_PASSWORD; printf '\n'
read -r -s -p 'Пароль преподавателя: ' DEMO_TEACHER_PASSWORD; printf '\n'
read -r -s -p 'Пароль деканата: ' DEMO_DEAN_STAFF_PASSWORD; printf '\n'
read -r -s -p 'Пароль бухгалтерии: ' DEMO_ACCOUNTING_STAFF_PASSWORD; printf '\n'
export DEMO_STUDENT_A_PASSWORD DEMO_STUDENT_B_PASSWORD DEMO_TEACHER_PASSWORD
export DEMO_DEAN_STAFF_PASSWORD DEMO_ACCOUNTING_STAFF_PASSWORD
export DEMO_SEED_ALLOW_PRODUCTION=YES_I_HAVE_A_BACKUP
bash scripts/production-compose.sh run --rm \
  -e DEMO_STUDENT_A_PASSWORD -e DEMO_STUDENT_B_PASSWORD -e DEMO_TEACHER_PASSWORD \
  -e DEMO_DEAN_STAFF_PASSWORD -e DEMO_ACCOUNTING_STAFF_PASSWORD \
  -e DEMO_SEED_ALLOW_PRODUCTION \
  migrate python scripts/seed_demo_data.py
unset DEMO_STUDENT_A_PASSWORD DEMO_STUDENT_B_PASSWORD DEMO_TEACHER_PASSWORD \
  DEMO_DEAN_STAFF_PASSWORD DEMO_ACCOUNTING_STAFF_PASSWORD DEMO_SEED_ALLOW_PRODUCTION
```

Это запускает seed отдельным контейнером `migrate` с ограниченной для API не
являющейся runtime-ролью `uni_space_migrator`; `uni_space_api` дополнительных прав
не получает. Повторное применение используйте только на той же БД и с теми же
паролями. Несовпадающий пароль, неожиданное состояние записи или неоднозначная
принадлежность seed приводит к отказу транзакции без автоматической ротации
паролей и без изменения посторонних записей. Повторный seed не является
восстановлением backup и не заменяет проверку данных.
